## Исправления

- `invocation_seconds` отдельно ограничивает рабочий/проверочный вызов;
  default 900 секунд. Существующий `max_seconds` остаётся общим бюджетом
  от первоначальной регистрации, default 600. Фактический вызов ограничен
  меньшим остатком; preflight повторно проверяет общий deadline.
- У preflight sandbox probe предел 20 секунд, у поиска существующего
  credential — 10; quota probe сохраняет отдельный предел 45 секунд.
  Остановка процесса допускает до шести секунд на TERM/KILL/reap, без новой работы.
- Claude выдаёт `stream-json`, verbose и partial events. Codex сохраняет
  JSON event stream. Сырые потоки и process metadata сохраняются в приватном
  `attempts/<id>/`, независимо от временного HOME. SQLite получает каждые
  15 секунд PID, elapsed и размеры stdout/stderr. Это признаки жизни,
  не доказательство полезного прогресса. Тишина не вызывает idle timeout.
- Новый `execution.py` проверяет PID и группу, завершает обычных потомков
  и сохраняет потоки даже при исключении callback или operator interrupt.
- Тайм-аут — отдельный outcome с `limited: false`. Он не меняет availability
  и не создаёт сигнал квоты. Перед checkpoint дополнительно проверяются
  фактическая остановка группы, scope, содержимое, ключи и symlink policy.
- Default `timeout_recovery: hold` сохраняет и проверяет безопасный checkpoint,
  затем держит его без commit/handoff. Явное `checkpoint` разрешает продолжение
  только для доверенной локальной, повторяемой файловой работы без внешних
  побочных действий и с непустыми внешними проверками. Неопределённые исходы
  без durable outcome всегда требуют inspection.
- Разрешённое продолжение использует прежний fingerprint/commit/atomic handoff
  протокол, увеличивает retry, сохраняет первоначальные лимиты и требует
  проверки завершения плюс свежий review. Review fallback остаётся opt-in.
  `execution.py` включён в digest безопасности unattended authorization.
- Approve проверяет и PID, и PGID. Старые holds, кодовые авторизации,
  scheduler configuration и исходные результаты не мигрируются автоматически.

## Ограничения и дальнейшее использование

Ночная миссия остаётся WAITING_APPROVAL с исходными лимитами и артефактами.
Её deadline нельзя сбрасывать для удобства тестирования. Решение о новой
авторизованной миссии/ручном восстановлении требует отдельной оценки файлов и
исходных действий; данный PR её не возобновляет и не меняет установленный job.

PID/PGID подтверждают остановку нормальной CLI process group. Намеренно
отсоединённые/untracked процессы и удалённые побочные действия этим не
доказываются: для таких задач нельзя разрешать автоматический checkpoint retry.
При неизвестном процессе или изменённом checkpoint применяется hold.
Обычный SIGKILL Runner до записи outcome тоже остаётся неопределённым исходом,
без автоматического повтора модели.

PR базируется на `feat/automatic-quota-resume`; включает необходимый локальный
патч очереди `784e23b` и исправления Mission 09. Публикация отдельного Draft PR
разрешена заданием Mission 09. Merge, deployment, обновление действующего
планировщика и возобновление ночной миссии не выполняются.
